Vérifier que votre PC peut faire tourner le lab

Virtualisation activée dans le firmware, assez de RAM et de disque.

VOTRE POSTEPowerShell administrateur
HÔTEvirtualisation
# Le processeur supporte-t-il la virtualisation, et est-elle activée dans le BIOS ?
Get-ComputerInfo -Property "HyperV*"
AttenduHyperVRequirementVirtualizationFirmwareEnabled : True
✕
Si c’est False : la virtualisation est désactivée dans le BIOS/UEFI. Redémarrez, entrez dans le BIOS et activez Intel VT-x ou AMD-V.

Ressources de l’hôte

RAM totaleminimum 12 Go · confortable 16 Go
Espace disque libreminimum 80 Go · confortable 150 Go
Processeurminimum 4 cœurs · confortable 8 cœurs
minimumjusqu’au confortable
!
12 Go de RAM, c’est juste. Les deux VM demandent 4 Go chacune au démarrage. Laissez la mémoire dynamique activée (c’est le cas dans le script) et fermez les autres applications.

Activer Hyper-V

Une fonctionnalité Windows à activer une fois, suivie d’un redémarrage.

VOTRE POSTEPowerShell administrateur
HÔTEétat actuel
# Hyper-V est-il déjà là ?
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All |
    Select-Object FeatureName, State

Si State : Disabled :

HÔTEactivation
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -All
↻
Redémarrage obligatoire après cette commande.
✕
La fonctionnalité n’apparaît pas du tout ? Vous êtes en Windows Famille / Home, qui n’a pas Hyper-V. Il faut Windows Pro, Entreprise ou Éducation. Alternative documentée : VMware Workstation.

3

Créer le réseau virtuel du lab

L’étape que tout le monde bâcle — et celle qui fait échouer le TP trois heures plus tard.

VOTRE POSTEPowerShell administrateur
3.1

Créer le switch virtuel interne

HÔTEswitch
New-VMSwitch -Name "vSwitch-Rennes" -SwitchType Internal

Pourquoi Internal et pas External ?

✕External

Les VM sont branchées sur le réseau de la salle et prennent une IP en DHCP. Si 12 élèves créent 12 domaines ad.fournil.lab sur le même LAN : conflits DNS, machines qui rejoignent le mauvais domaine… le chaos.

✓Internal

Un réseau privé entre vos VM et votre PC uniquement : chacun son lab, isolé. Seul inconvénient, pas d’Internet — on corrige ça avec le NAT en 3.3.

3.2

Donner une IP à l’hôte sur ce réseau

Le switch interne a créé une carte réseau virtuelle sur votre PC. C’est elle qui servira de passerelle aux VM.

HÔTEIP de la passerelle
# Retrouver l'index de cette nouvelle carte
$idx = (Get-NetAdapter -Name "vEthernet (vSwitch-Rennes)").ifIndex
$idx

# Lui donner l'adresse .254 — ce sera la passerelle des VM
New-NetIPAddress -InterfaceIndex $idx -IPAddress 192.168.3.254 -PrefixLength 24
3.3

Activer le NAT pour donner Internet aux VM

HÔTENAT
New-NetNat -Name "NAT-Fournil" -InternalIPInterfaceAddressPrefix 192.168.3.0/24
3.4

Vérification

HÔTEcontrôle
Get-VMSwitch -Name "vSwitch-Rennes" | Select-Object Name, SwitchType
Get-NetIPAddress -IPAddress 192.168.3.254 | Select-Object IPAddress, InterfaceAlias
Get-NetNat -Name "NAT-Fournil" | Select-Object Name, InternalIPInterfaceAddressPrefix
AttenduUn switch Internal, l’IP 192.168.3.254 sur la carte vEthernet (vSwitch-Rennes), un NAT sur 192.168.3.0/24.
New-NetNat : L’objet existe déjà ou conflit

Un ancien NAT traîne. Listez-les et supprimez celui qui gêne :

HÔTEnettoyage
Get-NetNat
Remove-NetNat -Name "<nom>" -Confirm:$false
!
Windows n’accepte qu’un seul NAT à la fois par préfixe.

5

Créer les deux VM

Copiez le bloc entier : il crée DC01 et DC02 d’un coup.

VOTRE POSTEPowerShell administrateur
HÔTEcréation de DC01 et DC02
# ====== Variables ======
$IsoPath = "D:\HyperV\ISO\ws2025.iso"
$VmRoot  = "D:\HyperV"
$VhdRoot = "D:\HyperV\VHD"
$Switch  = "vSwitch-Rennes"
$VhdSize = 80GB
$RAM     = 4GB
$CPU     = 4

foreach ($VMName in "DC01","DC02") {

    $VmPath  = Join-Path $VmRoot $VMName
    $VhdPath = Join-Path $VhdRoot "$VMName.vhdx"

    New-VM -Name $VMName -Generation 2 `
           -MemoryStartupBytes $RAM `
           -Path $VmPath `
           -NewVHDPath $VhdPath -NewVHDSizeBytes $VhdSize `
           -SwitchName $Switch

    Set-VM -Name $VMName -ProcessorCount $CPU

    # Monter l'ISO et démarrer dessus
    Add-VMDvdDrive -VMName $VMName
    Set-VMDvdDrive -VMName $VMName -Path $IsoPath
    Set-VMFirmware -VMName $VMName -FirstBootDevice (Get-VMDvdDrive -VMName $VMName)

    # Mémoire dynamique : la VM rend la RAM qu'elle n'utilise pas
    Set-VMMemory -VMName $VMName -DynamicMemoryEnabled $true `
                 -MinimumBytes 2GB -StartupBytes 4GB -MaximumBytes 8GB

    Write-Host "VM $VMName creee" -ForegroundColor Green
}

Ce que font les paramètres importants

-Generation 2VM en UEFI, le choix recommandé pour Windows Server 2025.
-NewVHDSizeBytes 80GBDisque dynamique : il ne prend que la place réellement utilisée (~15 Go au début).
Set-VMFirmware -FirstBootDeviceForce le démarrage sur le DVD, sinon la VM boote sur un disque vide.
-DynamicMemoryEnabled $trueLa VM rend la RAM inutilisée à votre PC — vital si vous avez peu de mémoire.

Vérification

HÔTEcontrôle
Get-VM DC01,DC02 | Format-Table Name, State, Generation, MemoryStartup, ProcessorCount
Get-VMNetworkAdapter DC01,DC02 | Format-Table VMName, SwitchName
AttenduDeux VM en état Off, Generation 2, toutes deux sur vSwitch-Rennes.
