Étape 00 · 10 min

Votre mission

À lire sur votre poste

Construire le système d’information du Fournil, puis prouver qu’un salarié accède aux bonnes données.

Le contexte

Une boulangerie, deux entités

Le Laboratoire fabrique. La Vente commercialise et gère les ressources. Les deux CSV décrivent l’organisation et les 30 salariés.

Votre utilisateur témoin sera Marc Lebrun, AD\mlebrun, du service boulangerie.

La démonstration finale

Une session qui fonctionne

  • Marc peut modifier les fichiers de boulangerie.
  • Il lit le dossier parent fabrication sans y écrire.
  • Son lecteur H: ouvre son dossier personnel.
  • « Mon Dossier Personnel » apparaît automatiquement dans l’Explorateur.
  • Un fichier métier se réplique entre DC01 et DC02.

Choisissez la façon de travailler

Les étapes restent identiques. Les consignes et le périmètre changent avec le niveau sélectionné en haut de page.

Débutant

Un service et un salarié, à la main. On déploie Laboratoire / fabrication / boulangerie et le home de Marc. Pas de test sur une ressource Vente inexistante.

CSV

Les 30 salariés et toute l’organisation, avec variables et boucles. Aucune fonction à écrire. DFS et les homes sont ensuite étendus à toutes les branches.

Avancé

Même périmètre complet. Vous écrivez vos scripts réutilisables, avec contrôles, journal et réexécution sans doublons.

Le fil à garder : réseau → domaine → objets AD → droits NTFS → partages SMB → DFS → réplication → homes → GPO → tests utilisateur. Un raccourci ne crée ni les droits ni le dossier vers lequel il pointe.

Préparez votre dossier de preuves

Créez un document recette-fournil. Pour chaque étape, conservez le résultat des commandes de contrôle, une capture utile et une phrase expliquant ce qui fonctionne. Les cases cochées seules ne constituent pas une preuve.

Temps indicatif : environ 8 à 10 h pour le parcours manuel complet, installation et mises à jour comprises. Le scripting et l’extension aux 30 salariés demandent du temps supplémentaire selon votre aisance.

Étape 01 · 60–90 min

Monter la maquette

Trois rôles, trois endroits. Le poste hôte lance les VM. DC01 sert à administrer le domaine. CLI01 sert à ouvrir la session du salarié. DC01 et DC02 cumulent fichiers et annuaire pour cette maquette pédagogique.

1. Choisissez un seul hyperviseur

  1. Vérifiez la virtualisation, les droits administrateur et la présence d’Hyper-V sur l’hôte.
  2. Créez un commutateur interne, une interface hôte 192.168.3.254/24 et le NAT du réseau 192.168.3.0/24.
  3. Créez DC01 et DC02 sur ce switch : 2 vCPU, 2 à 4 Go de RAM chacune et un disque adapté à Windows Server.
Procédure Hyper-V détaillée ↗
  1. Dans Virtual Network Editor, configurez VMnet1 Host-only, réseau 192.168.3.0/24, DHCP VMware désactivé.
  2. Attribuez 192.168.3.254/24 à l’interface VMnet1 de l’hôte et utilisez le NAT Windows prévu dans la procédure.
  3. Créez DC01 et DC02 sur VMnet1. Conservez ce réseau pendant tout le projet.

Le plan du TP n’utilise pas VMnet8 : sa passerelle peut entrer en conflit avec l’adresse de DC02. PowerShell Direct ne fonctionne pas avec VMware ; utilisez les consoles des VM.

Procédure VMware détaillée ↗

2. Installez les systèmes

  1. Installez Windows Server 2025 avec expérience utilisateur sur DC01 et DC02.
  2. Ajoutez CLI01 : Windows 11 Pro/Entreprise/Éducation, sur le même réseau, en respectant les exigences de sa version. Prévoir environ 4 Go de RAM et l’espace disque nécessaire en plus des serveurs.
  3. Le formateur peut fournir CLI01 déjà installé. Une VM cliente existante convient si elle est connectée à ce réseau et peut rejoindre le domaine.
  4. Prenez un point de reprise des installations propres selon les consignes du formateur.

Réservez au moins 16 Go de RAM sur l’hôte pour travailler confortablement avec les trois VM, davantage si d’autres applications consomment beaucoup de mémoire.

Étape 04 · 25–40 min

Ranger les objets dans les OUs

DC01 · administration AD

Créer les conteneurs avant de créer les comptes et les groupes.

La structure cible

Fournil
├── Utilisateurs
│   └── Laboratoire → fabrication → boulangerie
├── Groupes
│   └── Laboratoire → fabrication → boulangerie
└── Ordinateurs
    └── Laboratoire → fabrication → boulangerie

Les flèches représentent des OUs imbriquées. La chaîne complète est déclinée sous les trois branches.

1. Initialiser votre session

DC01
Import-Module ActiveDirectory
$dn = (Get-ADDomain).DistinguishedName
$racine = "OU=Fournil,$dn"

Ces variables vivent dans le terminal courant. Réinitialisez-les si vous ouvrez un nouveau terminal.

2. Créer les OUs dans l’ordre

Créez Fournil, puis Utilisateurs, Groupes et Ordinateurs. Sous chacune de ces trois OUs, créez Laboratoire, fabrication puis boulangerie. Cela fait 13 OUs avec Fournil dans ce périmètre minimal.

Créez Fournil et les trois OUs de type, puis reproduisez tous les chemins de l’organigramme sous chacune. Dédupliquez les parents communs et ignorez les services vides. Périmètre attendu : 121 OUs avec Fournil.

Indice : créer une OU enfant
DC01 · exemple de syntaxe
New-ADOrganizationalUnit -Name "Fournil" -Path $dn
New-ADOrganizationalUnit -Name "Utilisateurs" -Path $racine
New-ADOrganizationalUnit -Name "Laboratoire" -Path "OU=Utilisateurs,$racine"

Continuez pour les autres branches. Si un objet existe déjà, inspectez-le ; ne supprimez pas toute l’arborescence pour relancer une commande.

Livrable avancé : une fonction qui crée une OU uniquement si elle manque et renvoie son DN. Vérifiez une deuxième exécution sans doublon.

3. Contrôler votre structure

DC01 · contrôle
Get-ADOrganizationalUnit -SearchBase $racine -Filter * |
    Sort-Object DistinguishedName | Select-Object Name, DistinguishedName

Expliquez ce DN : OU=boulangerie,OU=fabrication,OU=Laboratoire,OU=Utilisateurs,OU=Fournil,DC=ad,DC=fournil,DC=lab.

Étape 05 · 30–45 min

Construire la chaîne AGDLP

DC01 · administration AD

Séparer l’appartenance métier de l’attribution des droits.

A · mlebrun→G · boulangerie→DL · boulangerie_M→P · Modification NTFS

Les noms abrégés du schéma correspondent aux noms complets ci-dessous.

1. Créer les groupes de sécurité

À chaque niveau construit — entreprise fournil, entité Laboratoire, pôle fabrication et service boulangerie — créez un groupe G_ de portée Global et deux groupes DL_..._L et DL_..._M de portée DomainLocal. Placez-les dans les OUs Groupes correspondantes.

Périmètre : 4 groupes globaux et 8 groupes locaux de domaine. Exemple du service : G_Laboratoire_fabrication_boulangerie, DL_Laboratoire_fabrication_boulangerie_L, DL_Laboratoire_fabrication_boulangerie_M.

Périmètre complet : 40 groupes globaux et 80 groupes locaux de domaine, y compris le niveau entreprise.

2. Imbriquer dans le bon sens

  1. Le G_ du service devient membre du G_ du pôle ; le G_ du pôle entre dans celui de l’entité, puis dans G_fournil.
  2. Pour le service boulangerie, le G_ entre dans le DL_ de modification.
  3. Pour les niveaux parents fabrication, Laboratoire et fournil, les G_ entrent dans les DL_ de lecture.
Indice : qui reçoit qui ?
DC01 · exemple
Add-ADGroupMember -Identity "G_Laboratoire_fabrication" -Members "G_Laboratoire_fabrication_boulangerie"
Add-ADGroupMember -Identity "DL_Laboratoire_fabrication_boulangerie_M" -Members "G_Laboratoire_fabrication_boulangerie"
Add-ADGroupMember -Identity "DL_Laboratoire_fabrication_L" -Members "G_Laboratoire_fabrication"

-Identity reçoit le membre désigné par -Members. Ne mettez pas un groupe DomainLocal dans un Global.

Au niveau complet, répétez la règle sur les branches de l’organigramme. Les groupes des nœuds terminaux portent la modification ; les parents permettent la lecture de leur propre niveau.

3. Vérifier avant d’appliquer des droits

DC01 · contrôle
Get-ADGroup -Filter * -SearchBase "OU=Groupes,$racine" |
    Select-Object Name, GroupScope
Get-ADGroupMember "DL_Laboratoire_fabrication_boulangerie_M" -Recursive
Get-ADGroup "G_Laboratoire_fabrication_boulangerie" -Properties MemberOf |
    Select-Object -ExpandProperty MemberOf

À ce stade, aucun utilisateur n’a encore été ajouté. Vérifiez les groupes imbriqués directement ; le test avec Marc arrive ensuite.

Étape 07 · 35–50 min

Publier les dossiers avec SMB et DFS

DC01 · local et Invoke-Command vers DC02

Fournir un chemin réseau stable qui peut pointer vers deux serveurs.

1. Préparer les deux cibles

Installez DFS Namespace et DFS Replication avec les outils sur DC01 ; DFS Replication sur DC02. Créez la même arborescence métier sur DC02 et contrôlez les ACL des deux serveurs. Créez sur chaque serveur le partage caché fabrication$ vers C:\fournil\Laboratoire\fabrication.

Donnez aux groupes concernés un accès SMB compatible avec les droits NTFS. Le droit réellement obtenu doit passer les deux filtres, SMB et NTFS. Le suffixe $ masque le partage dans la navigation ; il ne constitue pas une protection.

DC01 · contrôle des partages
Get-SmbShare -Name 'fabrication$'
Get-SmbShareAccess -Name 'fabrication$'
Invoke-Command -ComputerName DC02 {
    Get-SmbShare -Name 'fabrication$'
    Get-SmbShareAccess -Name 'fabrication$'
}

2. Créer l’espace de noms

  1. Sur DC01, créez le dossier de racine C:\DFSRoots\Laboratoire et le partage Laboratoire.
  2. Créez une racine de domaine DomainV2 : \\ad.fournil.lab\Laboratoire, hébergée par \\DC01\Laboratoire.
  3. Créez le dossier DFS fabrication et ajoutez ses cibles \\DC01\fabrication$ et \\DC02\fabrication$.
  4. Activez l’énumération basée sur l’accès si demandée. Elle agit sur l’affichage, les ACL restent nécessaires.
DFSn ≠ DFSr. Le namespace donne une adresse commune. Il ne copie pas les fichiers entre ses cibles. Les fichiers seront répliqués à l’étape suivante. Ici la racine DFS n’est hébergée que sur DC01 : deux cibles de données ne rendent pas la racine elle-même redondante.

Après validation de fabrication, déclinez les racines Laboratoire et Vente et les partages par pôle à partir du CSV.

3. Vérifier le chemin logique

DC01 · contrôle
Get-DfsnRoot -Path '\\ad.fournil.lab\Laboratoire'
Get-DfsnFolderTarget -Path '\\ad.fournil.lab\Laboratoire\fabrication'

Attendu : une racine de domaine et deux cibles pour fabrication. Le test de modification de Marc visera le sous-dossier ...\fabrication\boulangerie, pas le parent fabrication.

Étape 08 · 30–45 min + convergence

Répliquer les données métier

DC01 · administration DFSr

Prouver que les contenus circulent entre DC01 et DC02 dans les deux sens.

1. Construire le groupe de réplication

Pour fabrication, créez Laboratoire-fabrication-Replication, un dossier répliqué nommé fabrication, les deux membres DC01 et DC02 et les connexions nécessaires. Définissez sur chaque membre le chemin local C:\fournil\Laboratoire\fabrication.

Désignez DC01 comme membre principal pour l’initialisation. Après la synchronisation initiale, les deux membres peuvent recevoir des modifications. « Principal » ne signifie pas serveur maître permanent.

Dans ce lab, un contenu est préparé sur DC01 et la cible DC02 est vide avant l’initialisation. Faites vérifier tout contenu préexistant par le formateur.

Procédure DFSr détaillée ↗

2. Observer avant de tester

DC01 · contrôle
Get-DfsrMembership -GroupName 'Laboratoire-fabrication-Replication' |
    Select-Object ComputerName,FolderName,ContentPath,Enabled
Get-DfsrConnection -GroupName 'Laboratoire-fabrication-Replication'

Vérifiez les membres et les chemins, puis les événements DFS Replication en cas de blocage. La publication de la configuration dans AD et la synchronisation prennent un délai variable ; un délai fixe de 30 secondes n’est pas un critère de réussite.

3. Faire un aller-retour réel

DC01 · test aller
Set-Content 'C:\fournil\Laboratoire\fabrication\preuve-aller.txt' 'Depuis DC01'
Invoke-Command -ComputerName DC02 {
    Get-Content 'C:\fournil\Laboratoire\fabrication\preuve-aller.txt'
}

Attendez la convergence puis relancez uniquement la lecture sur DC02. Créez ensuite preuve-retour.txt sur DC02 avec Invoke-Command et lisez-le sur DC01. Conservez les deux résultats dans votre recette.

Déclinez ensuite la configuration et les contrôles sur les autres pôles du CSV.

À expliquer : réplication AD, réplication des données métiers et sauvegarde répondent à des besoins différents. Une suppression peut elle aussi être répliquée.

Étape 10 · 30–45 min

Automatiser l’emplacement réseau

DC01 · GPMC / CLI01 · session de Marc

Faire apparaître « Mon Dossier Personnel » à l’ouverture de session.

1. Comprendre le script fourni

Ouvrez C:\Deploy\Set-NetworkLocation.ps1. La version livrée avec ce guide interroge l’annuaire via LDAP et n’exige pas le module ActiveDirectory sur CLI01. Elle lit HomeDirectory puis crée un emplacement réseau vers ce chemin.

Expliquez : le rôle de Desktop.ini, du CLSID, de target.lnk et du contrôle d’existence. Vérifiez que le script utilise bien le home de l’utilisateur connecté, pas un chemin fixe vers Marc.

2. Créer et lier la GPO

Dans gpmc.msc sur DC01, créez GPO_Emplacement_Home et liez-la à OU=Fournil,DC=ad,DC=fournil,DC=lab. Conservez un filtrage qui inclut les utilisateurs visés. Le paramètre est une configuration utilisateur : Marc doit se trouver sous cette OU.

3. Enregistrer le script avec l’éditeur de stratégie

  1. Modifiez la GPO : Configuration utilisateur → Stratégies → Paramètres Windows → Scripts (ouverture/fermeture de session).
  2. Ouvrez Ouverture de session, onglet Scripts PowerShell, puis Afficher les fichiers.
  3. Copiez le script fourni dans le dossier Logon de cette GPO.
  4. Ajoutez ce script dans la liste et appliquez.

L’éditeur enregistre le script et les métadonnées de la stratégie. Copier un fichier dans SYSVOL ou créer seulement un fichier INI ne suffit pas à prouver que la GPO est correctement configurée.

Défi d’automatisation : produire une GPO équivalente, avec référencement du script, extensions et version de stratégie cohérentes. Comparez le résultat dans la GPMC. Une simple présence de psscripts.ini ne valide pas le défi.

2. Distinguer les erreurs

Le chemin est introuvable

Dans l’ordre : DNS → connectivité → partage SMB direct → dossier DFS → état de ses cibles. Testez les chemins physiques avec un administrateur, puis refaites le test d’accès avec Marc.

Marc n’a pas le bon droit

Contrôlez son G_, les imbrications DL_, les droits SMB et NTFS, puis son jeton après reconnexion. Sur CLI01 : whoami /groups. Une liste de membres directs dans AD ne suffit pas à décrire le jeton effectif.

Les fichiers ne se répliquent pas

Comparez les chemins locaux et les memberships, les connexions, l’état de la synchronisation initiale et les événements DFS Replication sur les deux serveurs. Ne confondez pas un retard de réplication avec un droit utilisateur.

Le raccourci GPO n’apparaît pas

Vérifiez d’abord que le home fonctionne. Contrôlez ensuite l’OU de Marc, le lien et le filtrage de la GPO, gpresult, la présence du script sur les deux DC, sa déclaration dans l’éditeur et une véritable fermeture de session.
