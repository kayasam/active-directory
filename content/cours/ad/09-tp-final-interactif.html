01 Phase 1 · Fondations

Monter la maquette

Créer un réseau de lab et les machines qui vont y communiquer.

⏱ 60–90 minHÔTEHyper-V ou VMware Workstation

Choisissez un seul hyperviseur

  1. Vérifiez la virtualisation, les droits administrateur et la présence d’Hyper-V sur l’hôte.
  2. Créez un commutateur interne, une interface hôte 192.168.3.254/24 et le NAT du réseau 192.168.3.0/24.
  3. Créez DC01 et DC02 sur ce switch : 2 vCPU, 2 à 4 Go de RAM chacune, un disque adapté à Windows Server.
Procédure Hyper-V détaillée
  1. Dans Virtual Network Editor, configurez VMnet1 Host-only, réseau 192.168.3.0/24, DHCP VMware désactivé.
  2. Attribuez 192.168.3.254/24 à l’interface VMnet1 de l’hôte et utilisez le NAT Windows prévu dans la procédure.
  3. Créez DC01 et DC02 sur VMnet1. Conservez ce réseau pendant tout le projet.
!
Le plan du TP n’utilise pas VMnet8 : sa passerelle peut entrer en conflit avec l’adresse de DC02. PowerShell Direct ne fonctionne pas avec VMware ; utilisez les consoles des VM.
Procédure VMware détaillée

Installez les systèmes

  1. Installez Windows Server 2025 avec expérience utilisateur sur DC01 et DC02.
  2. Ajoutez CLI01 : Windows 11 Pro/Entreprise/Éducation, sur le même réseau, environ 4 Go de RAM.
  3. Le formateur peut fournir CLI01 déjà installé. Une VM cliente existante convient si elle est sur ce réseau et peut rejoindre le domaine.
  4. Prenez un point de reprise des installations propres selon les consignes du formateur.
i
Réservez au moins 16 Go de RAM sur l’hôte pour faire tourner les trois VM confortablement.

05 Phase 2 · Annuaire

Construire la chaîne AGDLP

Séparer l’appartenance métier (G) de l’attribution des droits (DL).

⏱ 30–45 minDC01administration AD

Créer les groupes de sécurité

À chaque niveau construit — entreprise fournil, entité Laboratoire, pôle fabrication, service boulangerie — créez un groupe G_ de portée Global et deux groupes DL_…_L et DL_…_M de portée DomainLocal. Placez-les dans les OUs Groupes correspondantes.

#
Périmètre : 4 groupes globaux et 8 groupes locaux de domaine. Exemple du service : G_Laboratoire_fabrication_boulangerie, DL_Laboratoire_fabrication_boulangerie_L, DL_Laboratoire_fabrication_boulangerie_M.
#
Périmètre complet : 40 groupes globaux et 80 groupes locaux de domaine, y compris le niveau entreprise.

Imbriquer dans le bon sens

  1. Le G_ du service devient membre du G_ du pôle ; celui du pôle entre dans celui de l’entité, puis dans G_fournil.
  2. Pour le service boulangerie, le G_ entre dans le DL_ de modification.
  3. Pour les niveaux parents (fabrication, Laboratoire, fournil), les G_ entrent dans les DL_ de lecture.
Indice : qui reçoit qui ?
DC01exemple
Add-ADGroupMember -Identity "G_Laboratoire_fabrication" -Members "G_Laboratoire_fabrication_boulangerie"
Add-ADGroupMember -Identity "DL_Laboratoire_fabrication_boulangerie_M" -Members "G_Laboratoire_fabrication_boulangerie"
Add-ADGroupMember -Identity "DL_Laboratoire_fabrication_L" -Members "G_Laboratoire_fabrication"

-Identity reçoit le membre désigné par -Members. Ne mettez jamais un groupe DomainLocal dans un Global.

Au niveau complet, répétez la règle sur toutes les branches : les nœuds terminaux portent la modification, les parents permettent la lecture de leur propre niveau.

Vérifier avant d’appliquer des droits

DC01contrôle
Get-ADGroup -Filter * -SearchBase "OU=Groupes,$racine" |
    Select-Object Name, GroupScope
Get-ADGroupMember "DL_Laboratoire_fabrication_boulangerie_M" -Recursive
Get-ADGroup "G_Laboratoire_fabrication_boulangerie" -Properties MemberOf |
    Select-Object -ExpandProperty MemberOf

Aucun utilisateur n’a encore été ajouté : vérifiez les imbrications de groupes ; le test avec Marc arrive ensuite.

Droit SMB du partage∩Droit NTFS du dossier=Droit effectif
$

Comprendre le script fourni

Ouvrez C:\Deploy\Set-NetworkLocation.ps1. Il interroge l’annuaire via LDAP (pas besoin du module ActiveDirectory sur CLI01), lit HomeDirectory et crée un emplacement réseau vers ce chemin.

Expliquez le rôle de Desktop.ini, du CLSID, de target.lnk et du contrôle d’existence. Vérifiez que le script utilise bien le home de l’utilisateur connecté, pas un chemin fixe vers Marc.

Créer et lier la GPO

Dans gpmc.msc sur DC01, créez GPO_Emplacement_Home et liez-la à OU=Fournil,DC=ad,DC=fournil,DC=lab. Conservez un filtrage qui inclut les utilisateurs visés. C’est une configuration utilisateur : Marc doit se trouver sous cette OU.

Enregistrer le script avec l’éditeur de stratégie

Configuration utilisateur›Stratégies›Paramètres Windows›Scripts (ouverture/fermeture)
  1. Ouvrez Ouverture de session, onglet Scripts PowerShell, puis Afficher les fichiers.
  2. Copiez le script fourni dans le dossier Logon de cette GPO.
  3. Ajoutez ce script dans la liste et appliquez.
!
L’éditeur enregistre le script et les métadonnées de la stratégie. Copier un fichier dans SYSVOL ou créer seulement un INI ne prouve pas que la GPO est correctement configurée.
★
Défi d’automatisation : produire une GPO équivalente, avec référencement du script, extensions et version de stratégie cohérentes. Comparez dans la GPMC. Une simple présence de psscripts.ini ne valide pas le défi.
